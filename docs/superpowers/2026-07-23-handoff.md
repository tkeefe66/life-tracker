**Decisions already made** (spec §12, don't re-ask):

  Account roles move to Settings; Insights reverts to a single Behavior view.
- **ATM withdrawals triage as `spending`** — no seventh flow, no schema change.
- **Income is shown, framed as a floor** ("at least"), because payroll splits
  with the unconnected SoFi account.
- Questions 4–6 (bulk-correction = one-shot no persisted rule; `--chart-bank`
  aliases `--chart-delivery`; no lock on the Money surface) stand at defaults.

**The one trap the plan exists to avoid — read this before Task 2.** `ambiguous`
is derived and recomputed from scratch on every sync, and `bank_flows.is_ambiguous`
reads `flow`, not `resolved_flow`. So a row the user has already triaged
reclassifies, re-flags, and would **reappear in the queue forever**. The fix is
NOT in `bank_flows` (keep it pure — that purity is what licenses the full-table
reclassify). It's a SQL filter: the triage query selects
`WHERE ambiguous = true AND user_flow IS NULL`. This is spec §6.4 and plan Task 2,
step 1. A second, smaller trap (Task 3): movement totals must filter to the
outflow side (`amount < 0`) before summing, or a two-row transfer double-counts.

**Task order and what each touches:**
1. `bank_flows.triage_signature` — pure counterparty token (no DB/IO).
2. `database.py` — triage query (the filter above) + bulk override writer.
3–4. new `app/money.py` — summary aggregate, then triage assembly (the
   `app/scorecard.py` role, DB→domain).
5. `app/routes.py` — four routes.
6. `frontend/src/lib.ts` — pure helpers + vitest (the triage-button →
   `user_flow` mapping is the whole correctness surface).
7. `BankSpendChart` + `TriageQueue` components, `--chart-bank` token.
8–10. Money screen + fifth tab, Insights cleanup, roles in Settings.
11. CLAUDE.md.

Follows the Override + Learning Pattern (CLAUDE.md): `user_flow` already exists
alongside `flow`, resolved via `COALESCE(user_flow, flow)` as `resolved_flow` in
`_BANK_TXN_SELECT`. A triage correction writes `user_flow`; never re-resolve in
Python.

## Gotchas learned this session (will bite again)

- **`.env`/`.env.example` are permission-gated.** A global deny on `Read(./.env.*)`
  used to catch the committed template too; it was narrowed 2026-07-23 to the real
  secret names. If a session reports it can't read `.env.example`, the rule got
  widened again — fix the rule, don't work around it. The real `.env` stays denied,
  so the user must edit it; scripts read it via a wrapper that loads dotenv and
  never prints values.
- **Verifying bank_flows against real data:** use the LOCAL SQLITE DB with real
  row shapes (`import database as db; db.get_bank_accounts(); db.get_all_bank_transactions()`).
  `bank_transactions.account_id` is a FK to `bank_accounts.id` (the integer PK),
  **NOT** `simplefin_id` — hand-built dicts keyed on `simplefin_id` silently match
  nothing. Replay via `match_pairs(fresh, window_days=PAIR_WINDOW_DAYS, accounts=accts)`
  then `classify_all(fresh, roles, pair_map, INCOME_PAYEE_HINTS)`.
  Note `INCOME_PAYEE_HINTS` is empty in local dev, so income shows 0 locally —
  pass `["DEMANDBASE INC PAYROLL"]` explicitly to reproduce prod.
- **The `/api/bank/debug` route returns `counts`/`totals`/`accounts`/`ambiguous`,
  not a `transactions` list.** Reading a `transactions` key returns nothing and
  looks like data loss — it isn't.
- **`pg_dump` must be ≥ the server major.** Railway Postgres is 18.3. nixpkgs'
  `postgresql` alias gives 16.4 and has no `postgresql_18`; pg_dump now comes from
  the PGDG apt repo (`nixpacks.toml`, `[phases.pgclient]`). If Railway bumps
  Postgres past 18, bump the `postgresql-client-NN` there or backups silently stop
  (`jobs/backup_db.py` records `error: pg_dump version mismatch` — visible in
  Settings, not in a crash).
- **Forcing a scheduled job without waiting:** `railway ssh --service web "<cmd>"`
  runs inside the container. The SSH shell does NOT inherit the app's
  `LD_LIBRARY_PATH`, so psycopg2 fails to import — prefix with
  `export $(tr '\0' '\n' < /proc/1/environ | grep -E '^LD_LIBRARY_PATH=')` and use
  `/opt/venv/bin/python`. Requires a registered SSH key (`railway ssh keys add`),
  which only the user can do.
